# Linkbuilding Docs Route

Маршрутизация контента в docs/ и learnings/ репозитория Linkbuilding. Агент сам определяет папку, формат и файл — сотрудник не должен разбираться в структуре.

---

## Алгоритм

### 1. Прочитать запрос

Получить от пользователя контент: текст, скрин, описание, цитату из чата. Определить суть.

### 2. Классифицировать по Route Definitions

| Маршрут | Критерии | Папка | Триггеры |
|---------|----------|-------|----------|
| **agreements** | Договорённости между людьми/командами; распределение зон; формальные соглашения | `docs/agreements/` | «договорились», «согласовали», «распределение зон», «кто за что отвечает» |
| **rules** | Правила, конвенции; что обязательно или запрещено; стандарты | `docs/rules/` | «правило», «так надо делать», «конвенция», «нельзя», «обязательно» |
| **how-to** | Инструкции «как делаем»; процессы; пошаговые руководства; чеклисты | `docs/how-to/` | «как мы делаем», «инструкция», «процесс», «пошагово», «чеклист» |
| **webmaster-prospecting** | Конкретный **способ поиска/отбора** вебмастеров, доноров, контактов; детальные гайды (в т.ч. со скринами) | `docs/how-to/webmaster-prospecting/` | «как находим вебмастеров», «способ поиска», «где ищем площадки», «проспектинг», «сорсинг доноров», «как я нахожу контакты» |
| **learnings** | Результаты тестов, гипотезы, что сработало / не сработало, кейсы | `learnings/` | «протестировали», «результат теста», «сработало», «не сработало», «гипотеза» |
| **inbox** | Неясно куда; противоречивые сигналы; смешанный контент | `docs/inbox/` | Fallback при неуверенности |

**Правило выбора:** если контент подходит под два маршрута, выбирать тот, где больше совпадений по критериям. Если уверенность < 70% — `docs/inbox/` или уточнить у пользователя.

**Уточнение для how-to:** если речь о **способе поиска вебмастеров/доноров** (источники, инструменты, отборы) — целевая папка **`docs/how-to/webmaster-prospecting/`**, один способ = один новый `kebab-case.md` (или дополнение существующего). Шаблон: `docs/how-to/webmaster-prospecting/TEMPLATE-webmaster-method.md`. Общие короткие how-to без привязки к проспектингу остаются прямо в `docs/how-to/` (как `negotiation-guide.md`).

### 3. Определить целевой файл

- Проверить существующие файлы в целевой папке — возможно, контент дополняет уже существующий документ.
- Если файла нет — создать новый. Имя: `kebab-case`, по теме (например, `article-type-classification.md`, `zones-responsibility.md`).
- Файл `learnings/` — по теме эксперимента (например, `evergreen-vs-news-conversion.md`).

### 4. Применить формат

**agreements:**

```markdown
# [Название соглашения]

## Суть
[1–2 абзаца: что договорились]

## Участники
[Кто договорился]

## Дата
YYYY-MM-DD
```

**rules:**

```markdown
# [Название правила]

[Что обязательно / что запрещено. Кратко.]
```

**how-to (общий):**

```markdown
# [Название процесса]

## Когда применять
[Триггер / ситуация]

## Шаги
1. ...
2. ...
```

**how-to → webmaster-prospecting** (детальный способ поиска):

- Использовать структуру из `docs/how-to/webmaster-prospecting/TEMPLATE-webmaster-method.md` (пошагово, таблица отборов, скрины в `assets/<slug>/`).
- Не сокращать до трёх строк, если пользователь дал материал для развёрнутого гайда.

**learnings:**

```markdown
## [Тема]
- Что тестировали: ...
- Результат: ...
- Кто: [имя]
- Когда: YYYY-MM
```

### 5. Создать / обновить файл

- Все пути относительно `internal/seo/linkbuilding/`.
- Если файл уже существует — дополнить (не перезаписывать), если контент новый. Если обновление существующего контента — перезаписать секцию.
- После записи сообщить пользователю: что записано, куда, почему эта папка.

### 6. При неуверенности

- Если маршрут неочевиден — предложить пользователю два варианта или положить в `docs/inbox/` с заголовком `# [Тема] — требует классификации`.
- Inbox пересматривается периодически; файлы из inbox переносятся в нужную папку после уточнения.
